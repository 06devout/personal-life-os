# Personal Life OS

## v1.0.2 · 2026-11-07

- 新增年度挑战 / 会籍进度独立存档、下一年度规划入口及完整备份恢复。
- 飞行记录支持仅年份、起降时间、跨日与经停；机型标准化，界面统一使用公里。
- 飞行足迹按出发 / 可选经停 / 到达顺序生成机场、航司清单，支持首次去重和完整顺序。
- 机场显示三字码及全名，航司显示 IATA 二字码及名称；未知资料填写一次后持久复用。
- 私人飞行记录、数据库、密钥、备份及 `prompt.md` 不纳入版本库。

一个可本地部署的单人生活记录系统：日记、时间线、日历、目标、旅行、会员计划与证件管理。业务数据保存在服务器本机 SQLite，而不是浏览器缓存；没有云服务、外部字体、分析追踪或运行时第三方依赖。

## 快速开始

需要 **Node.js 24 或更新版本**。当前开发环境为 Node.js 26.5.1。无需执行 `npm install`。

```sh
cd /Users/devout/Desktop/cmx/miscellaneous/scheduler
npm start
```

打开 `http://127.0.0.1:3000`。首次打开设置至少 12 字符的访问密码，此后使用同一密码登录。请妥善保存密码，当前没有邮箱找回功能。

首次启动仅创建默认活动分类，**不会擅自写入虚构日记**。在「空间设置 → 载入演示数据」可添加一次明确标注的虚构示例，所有示例都能编辑和删除。

开发时使用 `npm run dev`。关闭终端服务后网页不能保存新记录；重新启动服务即可继续，数据仍在。

## Docker 部署

```sh
docker compose up -d --build
docker compose logs -f
docker compose down
```

数据放在持久化命名卷 `life-data`，`down` 不会删除数据。**不要执行 `docker compose down -v`**，它会删除数据卷。默认仅将端口映射到本机。

Docker 配置已提供，但本次环境未实际构建 Docker 镜像。

## 使用方式

### 每日记录

- 首页「记录今天」新建或编辑当天日记；全局「快速记录」可添加其他内容。
- 每个日期只能有一条日记；同一天可有任意多条活动。
- 支持城市、国家、总结、Markdown 正文、心情、睡眠、步数、标签；详情页上传照片和文件。
- Markdown 支持标题、列表、加粗、行内代码、引用；不是完整 CommonMark 编辑器，不执行 HTML。
- 日历支持月 / 周 / 日视图、跳转日期；点击任意日期查看日记、活动及当天航班 / 入住。
- 首页「生活的足迹」与日历共用浏览年月，可选择尚未有记录的未来年份 / 月份。足迹仍展示全年热力图，并标出所选月份；点击「打开所选月份」进入日历。日历也可直接选择年月或具体日期。
- 浏览日期、年份和月 / 周 / 日视图会自动记在当前浏览器，切换页面、刷新或重新打开后恢复上次位置，不会自动跳回今天；需要时点击「回到今天」或日历「今天」。此偏好不是业务记录，不跨浏览器同步，清除浏览器站点数据会重置。
- 月 / 周 / 日历及日期详情标注元旦、除夕、春节、清明、端午、中秋、劳动节、中国国庆节、复活节、感恩节、平安夜和圣诞节。同一天多个节日同时显示；首页足迹的日期悬浮提示也包含节日。
- 节日标注是节日本身，**不是法定连休、调休、补班安排**。春节标正月初一，除夕为农历年最后一天；感恩节采用美国 11 月第四个星期四，复活节采用西方教会公历算法。
- 农历与清明目前支持 **1901–2100 年**。农历使用内置历表，不依赖浏览器的 `Intl` 农历实现；清明用太阳视黄经近似算法计算 UTC+8 日期，并对多个跨日边界年份作回归测试。其他年份保留公历节日并明确提示农历 / 清明范围限制，不随意猜测。
- 这些标注完全本地生成、不写入个人日记，也不依赖联网 API。历表来源及授权见 `THIRD_PARTY_NOTICES.md`；日期样本对照 [香港天文台历表](https://www.hko.gov.hk/en/gts/time/conversion.htm)，复活节算法参照 [美国海军天文台](https://aa.usno.navy.mil/faq/easter)，感恩节规则参照 [美国 OPM](https://www.opm.gov/frequently-asked-questions/pay-and-leave-faq/pay-administration/what-are-federal-holidays/)。
- 周 / 日视图可用鼠标拖动活动到目标日期的整点时间槽，保留原时长。手机端或需要精确到分钟时使用编辑表单。
- 活动暂不跨午夜：请拆分为两天记录。允许活动时间重叠，统计会分别累计，不会自动扣除重叠时间。
- 在活动页「活动分类」或设置页管理分类。分类的「统计归类」决定学习 / 工作 / 运动等时长统计。
- 附件单文件上限 5MB；PNG、JPEG、GIF、WebP 可预览，其余下载查看。服务器核验图片文件头，不以内嵌形式打开 HTML / SVG / PDF。

### 挑战与累计

- 创建终身、年度、里程碑或自定义挑战，设置目标、单位、起止日期、初始值、里程碑及状态。
- 点击「+ 进度」添加正数或负数流水；详情页可编辑、删除手动流水。
- 当前值由「初始值 + 日期范围内手动流水 + 会员规则产生的累计」计算，不重复保存累计副本。
- 历史曲线按日期排列，达到目标后展示完成状态；预计达成日期是按开始以来的平均增长速度外推，不是承诺。
- 已暂停 / 失败状态不会停止计算历史流水，主要用于分类管理。进度达到目标时优先展示已完成。

### 旅行与会员入账

历史航班支持只填写年份：完整日期留空、填写「年份」，不会虚构月日；航班列表会显示「日期待补」，计入相应年度航班统计，但不落在某个具体日历日期。需补全日期后才能关联会员账户，以免错误归入保级周期。完整日期填写后年份自动同步。

航班另外支持起降当地时间、到达跨日天数（`+1` 单独记为 1）和经停机场。旧记录缺失的距离 / 票价保存为空，不当作实际为 0。**页面显示、添加及编辑表单统一使用公里**：首页、航班列表 / 详情、累计飞行、航司分布及年度存档均一致。为兼容旧数据库与备份，内部 `distance` / `flightMiles` 仍保留英里语义，在界面边界按 `1 英里 = 1.609344 公里` 转换，不批量改写距离，防止重复换算。原始公里数、机型、日期与时间保留在备注。会员奖励里程、定级积分和挑战自定义单位不作物理距离换算。

出发、到达及经停机场以 IATA 三字码显示（例如 PEK / HND / TFU）。已知中文机场名和航站楼后缀可自动转换，完整原始名称和航站楼保留在备注；已有三字码统一大写。未识别名称不猜测转换，可直接填写正确三字码。此为本地常用机场映射，并非全球机场目录。维护用 `node scripts/normalize-flight-airports.js [数据目录]` 会先在线备份数据库和密钥，再在事务中转换既有记录，重复执行不会重复添加原名。

维护用导入工具为 `node scripts/import-flight-log.js <私有输入JSON> [数据目录]`。工具先用 SQLite 在线备份保存数据库和密钥，再在事务中追加记录；同批次、同序号再次执行会跳过，不覆盖之后的手动修改。输入、备份及导入结果应留在已忽略的 `data/` 内，不提交个人行程到 Git。

导入时机型统一到系列 / 子型号，例如 `A321-213 → 321-200`、`A321-251(NX) → 321-200NEO`、`A330-243 → 330-200`、`A330-343(X) → 330-300`、`A330-941 → 330-900`，移除客户代码和翼梢标记，保留 NEO / ER 等实际机型差异。`A330-xxx` 仅标为「330（子型号未知）」，不猜测子型号。

1. 在「常旅客计划」创建航空 / 酒店账户，填写初始余额、年度 / 终身目标及保级周期。初始值应为尚未录入行程的起始余额，避免重复计入已存在的行程。
2. 在日历点击某一天，选择「添加航班」或「添加住宿」，日期自动带入；也可从快速记录或旅行档案添加。
3. 填写实际承运航司 / 酒店信息，单独选择「本次入账常旅客计划」。航班列出航空计划，住宿列出酒店计划。实际航司 / 酒店不决定入账账户，可以将不同承运航司的航班累计到同一个合作计划。
4. 默认「直接入账」，无需预建规则。未选择计划则只保存行程，不影响任何账户。

| 记录 | 填写字段 | 自动累计 |
| --- | --- | --- |
| 航班 | 本次奖励里程 | 所选计划余额 |
| 航班 | 本次年度定级积分 | 所选计划年度进度 |
| 航班 | 本次终身累计 | 所选计划终身进度；不默认等于飞行距离或奖励里程 |
| 住宿 | 合资格房晚 | 所选计划年度房晚 |
| 住宿 | 本次终身房晚 | 所选计划终身房晚；留空使用合资格房晚，填 0 表示本次不累计 |
| 住宿 | 本次奖励积分 | 所选计划积分余额 |
| 住宿 | 合资格消费 | 所选计划年度消费 |

修改数值后重新计算；换计划后从旧账户撤回并计入新账户；删除记录后撤回相应累计。年度进度与消费受账户保级周期限制，余额与终身累计不受年度周期限制。表单填写实际入账数值，不会自行根据品牌推测官方规则。

**高级规则可选：** 需要倍率换算或自动累计关联挑战时，配置规则并将该条记录改为「按高级规则」。直接入账与高级规则互斥，绝不叠加；会员积分流水继续按原有规则计算。

**兼容旧数据：** 已有记录和旧备份继续按历史规则快照计算，不会升级后突然补算或重复累计。编辑已有记录时保留原入账方式；只有主动切换到「直接入账」才使用新方式。高级模式下，改变账户、日期或从直接模式切回时匹配当前规则；仅修改数值仍使用历史快照。

规则可设置来源 → 原始指标 → 倍率 → 余额 / 年度 / 终身 / 消费，并可关联挑战。规则修改或删除不回溯改写历史快照。计划名称与阈值由用户维护，演示数据**不代表任何官方标准**。当前每条记录入账一个计划，暂不支持同一条记录拆分到多个计划。

### 证件与提醒

- 支持自定义证件类型、号码、签发 / 到期日期、续期标记、附件。
- 展示正常、180 / 90 / 30 天内到期和已过期状态；支持自定义提前提醒天数及多条具体日期提醒。
- 首页 / 顶栏提醒也包含会员到期、进度超过 80% 的进行中挑战和临近终身会员里程碑。
- 提醒在打开或刷新页面时重新计算，**没有后台邮件、手机通知或系统定时推送**。

### 统计与年度报告

「旅行档案 → 飞行足迹」自动生成机场到访顺序和航司乘坐顺序。默认按首次出现去重，显示首次日期、对应航班及累计次数，可切换到「完整顺序（含重复）」；每条列表项可以打开来源航班。新增、修改、删除航班后重新计算，无需维护第二份名单，也不受航班表格的搜索 / 排序影响。

#### 未知机场 / 航司：填写一次，永久复用

- 新建或编辑航班保存后，如果有未识别的机场或航司，会依次提示补全。可以点「稍后填写」，航班已经保存，不会因缺少资料而丢失记录。
- 在「旅行档案 → 飞行足迹」的「资料待补全」也能处理历史及未来计划中的未知条目。填写机场三字码 / 航司二字码、完整名称，按需添加别名，即可保存。原始未知名称会自动保留为别名，无需手工再次填写。
- 后续使用同一代码、名称或别名，均从本地 SQLite 资料库复用；刷新浏览器、换浏览器连接同一本地服务、重启服务后都有效。统计会自动重新识别并归并旧记录，不批量改写历史原文。
- 「机场 / 航司资料库」可新增、编辑、删除自定义资料。代码相同会更新对应名称，补全时合并别名；编辑资料时可调整别名。不能把已被另一代码占用的名称 / 别名再次分配，避免误合并；内置资料依旧作为基础映射。
- 这些是用户确认的资料，不自动联网验证官方真实性。未知项仍会明确标记，不凭空猜测代码。
- 设置页完整备份包含自定义资料库；导入会整体恢复它。旧版不含资料库的备份会恢复为空，操作前应先导出当前完整备份。删除自定义资料不删除飞行记录，但可能使别名重新成为待补全项。

- 机场按每段航班「出发 → 经停（可选）→ 到达」归入到访顺序，出发机场也算到访；默认按首次出现去重。列表同时显示三字码和完整中文名称，并标注首次记录是出发、经停还是到达。例如 PEK → HAK 的第一段航班，首次到访列表先列 PEK 再列 HAK。完整顺序中的次数为出发 / 经停 / 到达记录出现次数，不等同于不同旅行的到访次数。未收录的机场名明确显示待补，不猜测名称。
- 航司使用记录里的「航空公司」字段，常见中文名称 / 简称和代码（例如国航、中国国际航空、CA）合并；未知名称按原文保留，不根据航班号擅自猜测实际承运人。无法识别的别名暂不自动合并，建议使用一致的代码或名称。
- 航司列表与机场同样排版：上方大号大写 **IATA 二字码**，下方小字号中文航司名称；例如 CA / 中国国际航空、NX / 澳门航空。输入 IATA 两字码、ICAO 三字码或已知中文名称会归为同一家，原始航班号保持不变。未知映射显示「待补二字码」或「航司名称暂未收录」，不伪造代码。代码口径可参照 [IATA 航司资料](https://www.iata.org/en/about/members/airline-list/air-macau/321/)，历史航司保留历史身份，不合并进后来的收购方。
- 默认剔除出发日期晚于今天的计划，目的地到达日期还晚于今天的记录也暂不算已到达；可勾选「包含未来计划」，计划项目明确标记。按日历日期判断，不提供实时起降状态。
- 顺序基于年份、日期、出发当地时间；仅年份记录放在对应年份的日期待补组，按原表序号或录入时间排列，这只是信息不足时的展示分组，不代表早于该年所有日期完整的航班。同日时间未知的记录暂排该日末尾；无法在缺乏时区信息时保证实际 UTC 先后。
- 目的地日期使用记录的到达跨日偏移；经停没有独立日期 / 时间，列表只用原航班出发日期作参考，不能据此认定准确经停日期。

- 按年份汇总记录日、活动时长、每月睡眠 / 心情 / 步数、航班里程与航司分布、国家 / 城市、完成挑战和年度事件。
- 旅行天数按自然日合并去重，正确处理跨年旅行；跨年旅行国家和城市在相交年份计入。
- 国家 / 城市按手动输入的名称去重，因此请统一命名。多个名称使用中英文逗号分隔。
- 会员卡片展示当前保级周期与终身累计，不会假装拥有过去的会员等级历史。
- 统计页「导出年度报告 / PDF」调用浏览器打印，选择「另存为 PDF」。

### 年度存档与下一年规划

- 左侧「年度存档 → 创建年度存档」，选择今年或过去某年，填写名称和备注，即可保存一份只读进度快照。同一年可以创建多份独立版本，不覆盖之前的版本。
- 首页「生活的足迹」下新增「存档并规划下一年」：保存成功后可直接打开所存档年份的下一年一月日历。浏览未来年份时，此按钮默认保存当前现实年度的进度，不会给尚未到来的年份做虚假结算。
- 如果上一年有记录、挑战或会籍周期且尚未存档，刷新首页会显示提示；需要确认才保存，不会在跨年时擅自修改你的数据。若页面长期开着，需刷新页面获取新年提示。
- 快照保存挑战定义、目标、当前值、状态、历史进度，以及会员等级、余额、年度升级 / 保级目标、消费与终身进度，还有基本年度统计。不包含会员号码和照片附件；存档整体加密落盘。
- 今年存档的数据截止今天；补做过去年度存档截止当年 12 月 31 日，排除截止日之后的计划流水。会员年度进度仍按快照内显示的保级周期计算，不假设所有计划都在 1 月 1 日清零。
- **这是按存档时现有资料制作的快照，不是时间机器。** 若在存档前已经修改过会员等级、初始余额、保级周期或挑战定义，补做往年存档无法还原从未保存过的旧配置。建议在修改这些资料、或开启新一年的计划前先存档。
- 存档之后，即使原始挑战、会籍或流水被修改、删除，历史快照也不变。存档不能原地编辑，需要修订时创建新版本；删除存档需确认，不影响原始记录。
- 不自动复制下一年挑战、重置会籍初始值或切换保级周期，以免累计翻倍或破坏跨年会员周期。下一年的目标和周期仍由你单独维护。
- 可从存档详情导出单份 JSON 阅读 / 留存；**单份 JSON 不是业务数据库恢复包**。设置页的完整备份则包含全部存档，可一并导入恢复。恢复旧版、不含存档的完整备份，会将存档列表恢复为空，请在操作前另做完整备份。

## 数据、安全和备份

### 数据目录

```text
data/
  life.sqlite               SQLite 业务数据、密码哈希、会话及加密附件
  life.sqlite-wal           运行期间可能存在的事务日志
  life.sqlite-shm           运行期间可能存在的共享内存文件
  secret.key                32 字节本机加密密钥，务必备份
  before-import-*.json.enc   每次恢复之前保存的本机加密快照
```

数据目录权限设置为 `0700`，主数据库和密钥文件设置为 `0600`。证件号码、会员号码和附件使用 AES-256-GCM 随机 nonce 加密，密码使用 scrypt 加盐哈希；登录令牌仅在数据库保存 SHA-256 哈希，浏览器使用 HttpOnly / SameSite=Strict Cookie。

**不是全数据库加密。** 日记正文、日期、旅行和其他普通业务字段以明文保存在 SQLite；密钥和数据库位于同一设备，不能防御操作系统账户被攻破。请开启 FileVault / 磁盘加密并保护设备账户。

默认只监听 `127.0.0.1`，具有 Host 白名单、跨站写请求检查、登录失败限速、CSP 和关联删除保护。它是**单人本地系统**，不是面向公网的多用户服务。首次设置必须在可信设备进行。

### 前端导出 / 恢复

在「空间设置」导出完整 JSON 备份，包含所有业务记录、原始规则快照和附件；**导出文件中的敏感内容为明文**，下载前有提示，请存入加密盘或密码保险箱。

从 JSON 恢复会**完整替换**业务数据及附件，不是合并；账户密码及当前登录会话不会被替换。导入前自动保存加密本地快照，校验、插入和关联检查在事务中执行，失败则整体回滚。当前前端导入单个 JSON 上限 50MB；较大数据库请用停服目录备份方式。

### 停服目录备份（推荐用于长期归档 / 大附件）

1. 用 Ctrl+C 停止应用。
2. 完整复制 `data/` 到安全位置，必须包含 `secret.key`，不要遗漏仍然存在的 WAL 文件。
3. 恢复时先停服，将完整备份目录放回 `data/`，再启动。
4. Docker 用户应先停止容器，再通过 Docker 卷备份方式复制整个 `/app/data`。

密钥缺失时应用会拒绝打开已有数据库，避免生成不可用的替代密钥。导入前的 `.json.enc` 快照是应急保护；正常恢复优先使用前端 JSON 备份或完整目录备份。

## 环境变量

直接使用 shell 环境变量，不会自动读取 `.env`：

```sh
PORT=3080 DATA_DIR=/path/to/private-life-data TZ=Asia/Shanghai npm start
```

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `127.0.0.1` | 本机默认；Docker 内为 `0.0.0.0` |
| `DATA_DIR` | `./data` | 相对路径以启动目录为准，建议固定绝对路径 |
| `PUBLIC_HOST` | 未设置 | 额外允许的访问主机，形如 `192.168.1.10:3000` 或 HTTPS 域名 |
| `SECURE_COOKIE` | 未设置 | HTTPS 反向代理下设为 `1`；本机 HTTP 不设置 |
| `TZ` | 操作系统时区 | 统计与演示数据日期的服务器时区 |

手机访问需要部署机器可达，并配置 HTTPS 反向代理、`HOST`、`PUBLIC_HOST` 和合适的防火墙规则；请不要为方便访问直接将未加 HTTPS 的服务暴露公网。PWA 安装和 Service Worker 要求安全上下文，电脑 localhost 可用，手机普通局域网 HTTP 通常不可安装。

PWA 只缓存应用外壳，**不会缓存私人 API 响应，也没有离线写入队列**。必须连接本地服务才能查询和保存业务记录。

## 技术结构

为降低个人本地部署、维护和离线运行成本，本实现采用 Node.js 原生 HTTP / SQLite + 原生 ES Modules 前端，而未引入需求中建议（非强制）的 Next.js / Supabase。这不是静态页面或 localStorage 数据库。

```text
src/server.js                HTTP 路由、认证、附件下载与安全边界
src/store.js                 CRUD、加密、引用检查、事务导入导出
src/seed.js                  默认分类与显式演示数据
public/models.js            各实体字段定义和通用表单模型
public/metrics.js           前后端共用的统计与进度计算
public/app.js               页面、日历、表单、交互
public/styles.css           响应式样式与浅 / 深色主题
public/sw.js                PWA 应用外壳缓存
migrations/001_initial.sql  用户、会话、附件与迁移元数据
migrations/002_records.sql  业务实体、外键和关联索引
migrations/003_year_archives.sql  独立加密年度快照与版本索引
migrations/004_reference_directory.sql  可复用的机场 / 航司代码、名称及别名
src/archives.js              存档截止日筛选与年度快照生成
tests/                      存储、请求处理、前端渲染烟测
```

数据库按实体建独立表；可扩展属性放在经校验的 JSON 文档中，关联 ID 同时写入真实外键列并建立索引。迁移幂等且启动自动执行；后续结构变更应新增迁移，不修改已发布历史迁移。日记与航班 / 入住按自然日期关联，不要求添加航班前预先创建日记。
